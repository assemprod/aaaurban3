# AAA URBAN — адаптивный RU/KZ-сайт по согласованному референсу

Сайт на Next.js/Vinext для Cloudflare Workers. Русская главная — `/`, казахская — `/kz`. Помимо главной и SEO-страниц услуг, реализованы отдельные страницы компании, услуг, объектов и контактов на двух языках. База D1 текущей версии не требуется.

## Что изменено

- Главный экран повторяет композицию референса: оффер слева, архитектурное фото справа, мягкое белое раскрытие, две CTA и три смысловых индикатора.
- Основной оффер — бесплатный первичный аудит ЖК с прямым переходом в WhatsApp продажника.
- Навигация: «Главная / О компании / Услуги / Объекты / Контакты». Восемь SEO-направлений находятся внутри раскрывающегося подменю «Услуги» и не перегружают мобильное меню.
- Пять визуальных карточек показывают полный цикл: управление, техническую эксплуатацию, коммерческое управление, безопасность и сервис.
- Добавлены отдельные страницы `/about`, `/services`, `/objects`, `/contacts` и их казахские пары внутри `/kz`.
- `/about` выводит карточки сотрудников только из опубликованных записей `teamMembers` в `app/portfolio.ts`. Пока массив пуст, страница показывает нейтральный командный визуал без вымышленных имён и портретов.
- `/objects` выводит только опубликованные записи `caseStudies` из `app/portfolio.ts`; названия объектов, периоды и состав работ не берутся из демонстрационного макета.
- `/contacts` использует телефон, почту и адрес из `app/site-settings.ts`. Форма проверяет данные в браузере и готовит заполненное сообщение для WhatsApp, но не отправляет и не сохраняет заявку.
- Добавлена визуальная схема AAA URBAN: управление → эксплуатация → единая ответственность за результат.
- «Объекты» и «Доверие в цифрах» собраны в одной компактной композиции. Оригинальные цветные логотипы показаны отдельно как опыт группы.
- FAQ сохранён для ясности и SEO, а форма связи скрыта внутри раскрывающегося элемента финального CTA, чтобы не утяжелять страницу.
- На мобильном фото hero остаётся частью первого экрана и не переносится отдельным блоком вниз. Карточки услуг и объектов используют горизонтальный свайп; карточки команды появятся после публикации реальных сотрудников.
- Плавные появления, увеличение фото и медленное вращение инженерного знака отключаются при системной настройке «Уменьшение движения».
- Форма подготавливает сообщение в WhatsApp; посетитель проверяет его и отправляет сам.
- Настроены SSR, язык HTML, canonical, альтернативные языки, метаданные, Schema.org, robots.txt и sitemap.xml.
- Добавлены 8 отдельных SEO-страниц услуг на русском и 8 соответствующих страниц на казахском. Все страницы имеют собственный intent, H1, metadata, FAQ, Service schema и внутренние ссылки с главной.

## Важно перед финальной публикацией

Демонстрационные имена сотрудников, неподтверждённые объекты и показатели из визуального референса не публикуются. Главная и `/objects` используют подтверждённые записи `caseStudies`; карточки реальных сотрудников появятся только после заполнения `teamMembers`.

Контакты централизованы в `app/site-settings.ts`. Перед подключением рабочего домена владелец должен ещё раз подтвердить номер, WhatsApp, email и адрес.

## Где самостоятельно менять контакты

Откройте в GitHub **app → site-settings.ts → Edit**. Меняйте только значения в кавычках:

| Поле | Что указывать |
| --- | --- |
| `phoneDisplay` | Номер в удобном виде: `+7 701 220 01 12` |
| `phone` | Номер для звонка без пробелов: `+77012200112` |
| `whatsapp` | Номер продажника с кодом страны, без плюса: `77012200112` |
| `email` | Рабочая почта |
| `address.ru`, `address.kz` | Полный адрес на двух языках |
| `city`, `street` | Город и адрес для поисковых систем на двух языках |
| `siteUrl` | Основной адрес после подключения собственного домена |

Сохраните кнопкой **Commit changes**. При подключении GitHub к Cloudflare Builds новая публикация начнётся автоматически.

Переменная Cloudflare `NEXT_PUBLIC_SITE_URL` имеет приоритет над `siteUrl`. При смене домена обновите её или удалите, чтобы использовать значение из файла.

## Как добавить фотографии команды

1. Загрузите собственные фото в `public/team/`: WebP/JPEG, портрет 4:5, ширина от 800 px, около 150–300 КБ.
2. Откройте `app/portfolio.ts`.
3. Вместо пустого списка `teamMembers` внесите подтверждённые данные. Пример — шаблон, замените все значения:

```ts
export const teamMembers: TeamMember[] = [
  {
    id: "employee-01",
    name: { ru: "Имя сотрудника", kz: "Қызметкердің аты" },
    role: { ru: "Должность", kz: "Лауазымы" },
    photo: "/team/employee-01.webp",
    position: "50% 30%",
    published: true,
  },
];
```

Для нескольких сотрудников повторите объект `{ ... }`, разделяя их запятыми. `published: false` скрывает карточку. `position` регулирует положение лица в кадре.

Сейчас `teamMembers` пуст. Поэтому главная, `/about` и `/kz/about` показывают нейтральный иллюстративный визуал `public/media/management.webp` и готовую структуру блока команды. Сайт не использует `public/team/demo-*.webp`. Как только появится хотя бы одна опубликованная запись с непустым `photo`, нейтральный блок заменится карточками реальных сотрудников.

## Как добавить кейс ЖК

Загрузите согласованную фотографию в `public/cases/`. Добавьте запись в массив `caseStudies` файла `app/portfolio.ts`:

```ts
{
  id: "residential-01",
  category: "residential",
  title: { ru: "Название ЖК", kz: "Тұрғын үй кешенінің атауы" },
  scope: {
    ru: "Подтверждённый состав выполненных работ",
    kz: "Расталған жұмыстардың құрамы",
  },
  period: "Период работы",
  attribution: "urban",
  photo: "/cases/residential-01.webp",
  published: true,
},
```

Для опыта группы укажите `attribution: "group"`; для проекта AAA URBAN — `"urban"`. Поле `logo` необязательно. Не используйте иллюстративные фото как доказательство реального кейса.

Главная, `/objects` и `/kz/objects` используют опубликованные элементы `caseStudies`. На странице объектов доступны фильтры по корпоративным объектам и жилым комплексам; если в категории нет опубликованных записей, выводится нейтральное пустое состояние. При отсутствии `photo` карточка показывает нейтральную фирменную поверхность, а не фотографию другого объекта. Название, период и описание всегда берутся из `caseStudies`.

Текущие подтверждённые записи:

| Haileybury Astana | 2011 | Комплексное обслуживание объекта |
| Казатомпром | 2018 | Комплексное обслуживание головного офиса |
| Самрук-Казына | 2020 | Работа с противопожарными системами головного офиса |

## Как обновить существующий GitHub и Cloudflare

1. Распакуйте архив. Откройте папку с `package.json`.
2. Замените файлы в существующем репозитории, сохраняя вложенные папки. Не загружайте ZIP как один файл. Сохраните собственные изменения, если редактировали проект после прежнего экспорта.
3. Обязательно загрузите **vendor/shadcn-tailwind-4.13.0.css**: именно эта папка отсутствовала в предыдущей неудачной сборке.
4. В `wrangler.jsonc` имя Worker — **aaaurbanver2**. Блок D1 убран.
5. В настройках сборки существующего Worker:

| Настройка | Значение |
| --- | --- |
| Production branch | Рабочая ветка, обычно `main` |
| Root directory | Корень репозитория с `package.json` |
| Build command | `npm run build` |
| Deploy command | `npx vinext deploy --skip-build` |
| Node.js | `24.19.0` или совместимая версия 22.13+ |
| NEXT_PUBLIC_SITE_URL | `https://aaaurbanver2.corparationsite.workers.dev` до подключения домена |

6. Сохраните изменения в GitHub. Дождитесь успешной сборки и публикации Cloudflare.
7. Откройте `/` и `/kz`, затем четыре пары `/about`, `/services`, `/objects`, `/contacts` и `/kz/...` с телефона. Проверьте меню, переключение языка, фильтры объектов, основные CTA и номер WhatsApp. Для проверки формы на `/contacts` достаточно подготовить сообщение и открыть WhatsApp; отправлять тестовую заявку необязательно.

Архив содержит исходный код. Для публикации в вашем Cloudflare используйте собственное авторизованное подключение GitHub или Wrangler.

## Локальная проверка

```bash
npm ci
npm test
npx tsc --noEmit --incremental false
```

`npm test` собирает production Worker и проверяет главную, 8 новых RU/KZ-страниц, детальные страницы услуг, SEO, изображения, внутренние ссылки, номера WhatsApp и отключённый старый API. Браузерные клики и визуальное отображение эта команда не проверяет.

Для разработки: `npm run dev`. Для публикации с авторизованного компьютера: `npx wrangler login`, затем `npm run deploy`.

## Заявки, аналитика и Битрикс

- **WhatsApp:** работает без базы. Форма `/contacts` локально проверяет имя и телефон, формирует `wa.me`-ссылку с введёнными данными и предлагает открыть чат. Пользователь отправляет сообщение сам; в базе сайта заявки не сохраняются.
- **Битрикс:** пока не подключён. Для отправки форм в CRM нужны серверная интеграция, права и данные от специалиста заказчика. Секретный webhook нельзя размещать в `site-settings.ts`, клиентском коде или публичном GitHub.
- **Старый `/api/inquiries`:** возвращает статус 410, ничего не сохраняет и не требует D1. Старые открытые вкладки не получат ложное подтверждение заявки.
- **Аналитика:** события `cta_click`, `whatsapp_click`, `phone_click`, `email_click`, `object_select`, `section_view`, `inquiry_prepared` подготовлены в `dataLayer`. Имя, телефон и комментарий туда не передаются. GTM/GA4 не активированы без идентификаторов заказчика. Открытие WhatsApp не равно отправке сообщения.
- **Search Console:** подтверждение домена выполняется в аккаунте владельца; оно не заменяется sitemap.

Файлы `db`, `drizzle`, `examples/d1` сохранены как неиспользуемые заготовки старого экспорта. Текущий сайт не обращается к базе; запускать миграции не нужно.

Не загружайте в GitHub `node_modules`, `dist`, `.wrangler`, локальные `.env` и секретные ключи. В этом архиве их нет.
